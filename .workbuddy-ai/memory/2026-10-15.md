# 2026-10-15

## 前后端联调问题诊断（hello / zero-to-tech 模块 5.5）

**现象**：`curl http://localhost:8000/api/profile` 卡住无输出；浏览器 Network 面板只有静态资源，页面显示 0.86 / 偏积极（占位数据）。

**定位到的三个问题**

1. **8000 端口被卡死的 uvicorn 进程占着**（核心原因）
   - netstat：`127.0.0.1:8000 LISTENING` 被 PID 22488（reloader 父）与 PID 17936（worker）同时持有，属于 `fastapi dev` 的正常父子结构。
   - 但 TCP 能三次握手成功、发完请求后 20s 收不到任何字节（raw socket 实测 TimeoutError）；同一时刻 3000 端口和临时 8123 端口都秒回 200，说明是 8000 上这个进程假死，不是环境/防火墙问题。
   - 用同一个 venv 在 8001 端口新起 `uvicorn main:app` → `/api/profile` 200、`/api/analyze` 200，**证明代码本身没问题，是进程状态坏了**。
   - 系统里还有多组残留进程：fastapi.exe 35040 / 13120、python.exe 7096 / 27008（仅 3.4MB，几乎没启动起来）、python.exe 8840 / 35032，以及一个卡住的 curl.exe 532 —— 是反复启动后端留下的垃圾。

2. **环境里设了 HTTP 代理**：`http_proxy=HTTP_PROXY=https_proxy=HTTPS_PROXY=http://127.0.0.1:9663`。
   - curl 会走代理，于是报错变成「连到 9663 后超时」或对 `[::1]:8000` 返回 502 Bad Gateway，看起来完全不像后端问题。
   - 诊断时必须用 `curl --noproxy "*"`，否则一直在看代理的脸色。

3. **后端缺 CORS 中间件**（代码层面必改）
   - `backend/main.py` 没有 `CORSMiddleware`，响应里没有 `access-control-allow-origin`；`OPTIONS /api/analyze` 会 405。
   - 因此即使后端活着：主页 `/api/profile` 会被浏览器拦掉（回退到 `data/site.js`），文字实验室点「开始分析」会报错。
   - README（模块 5.5）明确写了「后端跟着课件加上 CORS 即可」，属于漏做的一步。

**结论**：先杀干净 8000 上的残留进程再重启后端；curl 验证加 `--noproxy`；再给 main.py 补 CORS。前端 `components/HomeView.jsx`、`InputCard.jsx` 里 `http://localhost:8000` 是写死的，后续按课程收进 `.env.local`。

## 补充：课件视频 vs 本机 Network 面板对比（同一 `/api/profile` 请求）

课件视频（老师）与用户本机同时截在同一张图里，页面内容完全一样（都是 site.js 打底），差别只在 DevTools 的 `profile` 那一行：

| | 老师（视频） | 用户本机 |
|---|---|---|
| 状态 | `CORS error`（红） | 空 |
| 时间 | **4 ms** | **挂起** |
| 条数 | 1 | 2 |

- 4ms 说明老师的后端**是活的**，响应被浏览器 CORS 检查拦掉（响应缺 `Access-Control-Allow-Origin`）；老师是在演示「没配 CORS → 回退到 site.js」。
- 「挂起」说明请求**一个字节都没回来**，即 8000 上进程假死 —— 用户的问题比老师演示的更靠前一层，两步都还没走到。
- 用户有 2 条 `profile`：React 开发模式 StrictMode 会把 `useEffect` 跑两遍，属正常现象。
- 修复顺序：重启后端（挂起 → CORS error）→ 加 CORSMiddleware（CORS error → 200，标题变「关于我(来自后端)」）。
